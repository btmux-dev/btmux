Use [Tailscale](https://tailscale.com) to give your server a private HTTPS
address you can open from another computer, tablet, or phone.

## With Tailscale

<Steps>

1. Install Tailscale on the server and on your other devices. Enable
   [MagicDNS](https://tailscale.com/kb/1081/magicdns) and
   [HTTPS certificates](https://tailscale.com/kb/1153/enabling-https) for the
   tailnet. btmux uses the `tailscale` CLI; on macOS, the one bundled with the
   Tailscale app works.

2. Start btmux with `--tailscale`:

   ```sh
   btmux --tailscale            # https://<machine>.<tailnet>.ts.net:8004
   btmux --tailscale install    # the same, as a background service
   ```

   In the desktop app, check **Share it on my tailnet** when starting a
   [desktop server that keeps running](../start/desktop.md#other-machines).

3. Open the URL printed at startup or shown by the status bar's tailnet
   button. Sign in as `btmux` with the
   [access token](../start/installation.mdx#server-only). The browser keeps
   the login for 400 days.

4. On a phone or tablet, scan the QR code from the tailnet button to sign in.
   Each code works once and expires after two minutes.

</Steps>

The [desktop app](../start/desktop.md#other-machines) on another machine can
connect to that URL too.

### What `--tailscale` does

`tailscale serve` forwards HTTPS requests for the machine's tailnet name to
btmux on `127.0.0.1`.

- It never replaces another route on that port. If one exists, btmux serves
  locally and says so: remove that route or choose another `--port`.
- Shutting down removes only a route btmux created; an upgrade keeps it.
- If Tailscale isn't running yet, btmux keeps serving locally and retries. If
  the route disappears later, for example after Tailscale restarts, it sets it
  up again.

The tailnet button shows the URL, or the last error.

HTTPS matters even though the tailnet is already encrypted: browsers allow the
clipboard, notifications, and WebGPU wallpapers only on secure origins.

## Without Tailscale

Put btmux behind a reverse proxy that terminates HTTPS, and tell btmux its
public address with `--public-url`. See
[Reverse proxies](../configuration/access.md#reverse-proxies).

## Forwarding a pane's port

A dev server started in a pane listens on the server's machine. To open it in
your own browser, with its devtools and extensions, or to reach a port that
isn't HTTP, such as a database or a debugger, forward the pane's port to your
computer:

```sh
btmux forward -t work:1.0            # the pane's only listening port
btmux forward -t work:1.0 5432       # one of several
btmux forward -t work:1.0 [::1]:8000 # a port held on several addresses
```

`btmux forward` prints a local URL, such as `http://127.0.0.1:5173/`, and
forwards each connection to it until you press `Ctrl+C`. It uses the pane's
port number locally when it's free, so sign-in redirects to `localhost` keep
working; `--local-port` picks another and `--open` opens the URL in your
browser. With several ports and none named, it lists them and exits 1, as it
does when different programs hold one port on different addresses: name one
as `ADDRESS:PORT`. When the pane closes, it exits 3.

Before printing the URL, it asks the server whether a connection would reach
the pane's program, without connecting to it, so a program that takes only one
connection, like a debugger, keeps it for you. On the server's own machine,
taking the pane's port number can stand in front of a program that listens on
every address; it then takes any free port instead.

In a pane, it forwards to your client's machine only if that is the server's
too. From another computer with btmux installed, name the server's URL; the
access token comes from `BTMUX_AUTH_TOKEN`, never the command line:

```sh
export BTMUX_AUTH_TOKEN=...          # the server's access token
btmux forward --server https://machine.tailnet.ts.net:8004 -t work:1.0
```

Only programs in the pane, or in its popups, can be reached. The server checks
each connection after making it: the program that accepted it, or the one
listening where it arrived, must be in the pane, so a program that took over
the port, or another listening on a more specific address, gets nothing.
`btmux list-panes` in a pane on the server shows pane IDs, and
`GET /api/panes/{id}/ports` the ports.

- A client may close its side of a connection and keep reading the reply.
- Connections open during a `btmux upgrade` or restart are reset. New ones
  wait up to 10 seconds for the server, including through a proxy answering
  502, 503, or 504 meanwhile.
- Panes of sandboxed sessions can't be forwarded yet.
- btmux connect doesn't carry forwards, so forwarding needs Tailscale, a
  reverse proxy, or the same network.

## On a phone or tablet

Phones, in either orientation, have no key bar or status bar. Large buttons
below the terminal open what you need most:

| Button | Opens |
| --- | --- |
| Keyboard | Keys on-screen keyboards lack: Esc, Tab, arrows, the prefix, and Ctrl and Alt, which apply to the next key. It stays open until you tap it again. |
| Keyboard, struck through | Hides the keyboard. |
| ⌘ | The command palette. |
| Robot | Agent view. It shows a dot when an agent is blocked or done. |
| Magnifier | The session switcher. |
| Folder, branch, pulse | The file browser, Git mode, and the process viewer. |
| Menu | The sessions and windows list, with settings. |

- A phone shows only a window's active pane, with a map of its panes beside
  the buttons: tap one to switch to it.
- Tablets and other touchscreens keep the status bar, with a key bar above it.
- Swipes scroll, including in full-screen programs such as `less`.
- On narrow screens the file browser and process viewer fill the screen.
- Key hints in footers can be tapped.
- Add btmux to the home screen to run it without browser chrome.
